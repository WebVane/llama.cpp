## 1. Что тестируем

Админ-панель веб-интерфейса Provision LLM Engine — страница `#/admin` (вкладка браузера называется `Admin - Provision LLM Engine`). Панель доступна только на сервере в режиме router с `PROVISION_ADMIN=1` и защищена отдельным admin-ключом (заголовок `X-Admin-Key`). Панель состоит из трёх вкладок: `Models` (список моделей, их загрузка/выгрузка, скачивание с Hugging Face, загрузка GGUF с компьютера, удаление, блок `GPUs`, строки хранилища), `Settings` (лимит одновременно загруженных моделей, GPU по умолчанию, закреплённые модели, блок `Server`, блок `Diagnostics`) и `Activity` (журнал аудита). К каждой модели есть диалог `Model settings` (12 настроек, проверка размещения «влезет ли в память», экспорт/импорт файла настроек) и диалог вывода модели `Output of <id>`.

Вне объёма этой инструкции: Windows-установщик, развёртывание сервера (Docker, compose, nginx, переменные окружения), сам чат. Всё, что требует действий на сервере, вынесено в раздел 6 «по заявке администратору стенда». Тестировщик работает только из браузера своего компьютера и (по желанию) из curl со своего компьютера.

## 2. Что нужно получить от администратора стенда

Чек-лист (записать до начала):

1. URL интерфейса `<URL>` (например `http://host:port` или `https://…`). Для curl ниже это `$BASE`.
2. Admin-ключ `<KEY>`. Вводится один раз в форму `Admin key required` на странице `#/admin` (поле `Admin key`, кнопка `Unlock`); в curl передаётся заголовком `X-Admin-Key: <KEY>`. Ключ нельзя пересылать в баг-репортах и скриншотах.
3. Подтверждение, что адрес тестировщика разрешён для `/admin` (иначе кнопки `Admin` не будет и все `/admin/*` вернут 403).
4. Задан ли на сервере обычный API-ключ (`--api-key`). Если да — UI сначала спросит его, а curl к `/admin/*` потребует ещё `Authorization: Bearer <api-key>`; 401 будет приходить от API-ключа, а не от admin-ключа (форма ответа: `401 {"error":{"code":401,"message":"Invalid API Key","type":"authentication_error"}}`).
5. Второй браузер или устройство (другой браузер, другой профиль или приватное окно считаются отдельным клиентом: ключ вводится в каждом отдельно). При включённом `Remember on this device` ключ лежит в localStorage и общий для всех вкладок и окон того же профиля браузера (новое окно того же профиля — не отдельный клиент); отдельным клиентом тогда являются только другой браузер/профиль или приватное окно. Для кейсов allow-list — второе устройство в другой сети (мобильный интернет/VPN) как «неразрешённый адрес».
6. Факты о стенде:
   - **GPU или CPU-only** и имена устройств (например `CUDA0`, `CUDA1`). Меняет: блок `GPUs` (карточки либо блок `CPU only.`), колонку `Placement` (`CPU` на CPU-only), селект `GPU for new models`, селект `GPU` в диалоге модели, вердикты проверки размещения (`Fits…`/`Runs on the CPU only`).
   - **Смонтирован ли `/models-rw`** (Docker) / где лежат каталоги на хосте. Если не смонтирован — над вкладками ожидается баннер `Model storage is not persistent…` и предупреждение в `Diagnostics` → `Model storage`.
   - **Включён ли allow-list / замок nginx** (`PROVISION_ADMIN_ALLOW_FROM`, `ADMIN_ALLOW_RULES`) и задан ли `PROVISION_ADMIN_TRUSTED_PROXIES`. Меняет кейсы ADM-API и раздел 6.
   - **Есть ли предзагруженные модели** (из `models.ini` — источник `preset`; из каталога моделей — `models dir`; из кэша Hugging Face — `cache`), их id, алиасы, имена секций `models.ini`.
   - **Есть ли выход в интернет** у сервера (скачивание с Hugging Face; в `GET /admin/status` с ключом поле `download.available`).
   - **Задан ли `--models-dir`** (без него вкладка `Upload GGUF` показывает блок недоступности, а кнопки `Delete files` нет).
   - **Задан ли `MODEL_DEVICES`** или серверные параметры вроде `--ctx-size` (блокируют поля в диалоге настроек).
7. Как связаться с администратором для кейсов раздела 6 и сколько времени занимает перезапуск.

## 4. Как фиксировать результат

**UI.** На каждый кейс — скриншот итогового состояния (вся страница, включая шапку с бейджами `Loaded N / M`, `N models`, уведомления над таблицей и toast в углу). Для диалогов — скриншот диалога целиком. При ошибке — дополнительно DevTools → Console (ошибки) и DevTools → Network: запрос, вернувший ошибку (URL, метод, статус, тело ответа; заголовок `X-Admin-Key` закрыть).

**Ширина окна.** Тестировать в окне браузера шириной не менее 1024 px. На более узком окне текстовые подписи кнопок скрыты (остаются иконки с title/aria-label): `Settings` / `Delete` / `Delete files` в таблице моделей показаны текстом только от 1024 px (aria-label `Settings of <id>`, `Delete <id>`, `Delete the files of <id>`), подпись `Refresh` в блоке `GPUs` и на вкладке `Activity` и подпись `back to …` в диалоге `Model settings` — только от 640 px; колонки `Tags` / `Source` / `Placement` ниже 768 px сворачиваются под имя модели. Отсутствие этих подписей на узком окне — не дефект.

**Вкладка `Activity`** — замена серверным логам. После каждого действия нажать `Refresh` и найти запись: изменения через панель → чип `Changes` (`Settings changed`, `Model settings changed`, `Model settings reset`, `GPUs re-detected`, `Upload started`, `Upload published`, `Upload cancelled`, `Upload rejected`, `Upload taken over`, `Model files deleted`, `Projector removed`; неуспешные — `… failed` с `HTTP <код> · <type>`); отказы доступа → `Refusals` (`Request refused`, `More refused requests`, `401 · wrong admin key`, `403 · address not allowed`); действия сервера → `Server` (`Audit log started`, `Model settings reverted`, `Model settings reverted at startup`, `Upload expired`, `Upload resumed after a restart`, `Abandoned upload removed`, `Audit log written again`); эффекты публичного API → `Public API` (`Download finished`, `Download failed`, `Model removed`, `Model failed to start`, `More public API events`). Клик по времени записи раскрывает три колонки `Details` / `Who` / `Record`; ниже свёрнутая строка `Raw record (JSON)` — клик по ней показывает JSON и кнопку `Copy record` (toast `Record copied`), которая копирует запись в буфер — вставлять в баг-репорт. Load/Unload/Rescan и все чтения записей не создают.

**curl (по желанию).** Шаблон:

```
# Linux/macOS
BASE=http://<host>:<port>; KEY='<admin key>'
curl -s -i -H "X-Admin-Key: $KEY" "$BASE/admin/status"
# Windows PowerShell (именно curl.exe: curl там алиас Invoke-WebRequest)
$BASE='http://<host>:<port>'; $KEY='<admin key>'
curl.exe -s -i -H "X-Admin-Key: $KEY" "$BASE/admin/status"
# POST с телом из файла
curl.exe -s -i -H "X-Admin-Key: $KEY" -H "Content-Type: application/json" -d @body.json "$BASE/admin/settings"
```

Ключевые поля: `GET /admin/status` (с ключом) — `authorized`, `key_source`, `features[]`, `models{max,running,total}`, `state{dir,writable,error,model_settings}`, `download{available,offline}`, `upload{available,reason,message}`, `audit{persisted,error,in_memory}`, `dirs{cache,models_dir,preset}`, `storage{container,persistent,ephemeral[]}`, `ip_allowlist`, `warnings[]`; `GET /admin/storage` — `dirs[{kind:cache|models_dir|state,path,exists,writable,looks_persistent,total_bytes,free_bytes}]`, `partial_downloads[]`, `uploads[]`, `upload_staging`, `audit.files[]`; `GET /admin/diagnostics` — `items[{id,label,status:ok|warning|error|info,value,hint}]`; `GET /admin/audit?limit=N` — `entries[{seq,kind,action,result,target,actor,details}]`, `next_before`, `matched`, `persisted`; `GET /admin/audit?format=jsonl` — файл `provision-admin-audit.jsonl`. Коды: 200 OK; 400 `invalid_request_error`; 401 `admin_key_required`; 403 `admin_forbidden`; 404 `not_found_error` (для `/admin/*` — `model '<id>' is not found`; для несуществующего пути, например опечатки в URL или сервера без `PROVISION_ADMIN=1`, — `File Not Found`); 409 `rescan_busy` / `rescan_stuck` / `restart_required` / `field_locked` / `default_device_locked` / `model_settings_read_only` / `not_deletable` / `name_taken` / `too_many_uploads` / `upload_busy` / `check_busy` / `check_stuck` / `model_running`; 410 `upload_gone`; 413 `chunk_too_large`; 422 `not_gguf`/`file_rejected`; 429 `upload_slots_busy`; 500 `server_error` / `write_failed`; 503 `admin_key_unavailable`; 504 `stop_timeout`; 507 `disk_full`. При заданном `--api-key` любой `/admin/*` без `Authorization: Bearer <api-key>` → `401 {"error":{"code":401,"message":"Invalid API Key","type":"authentication_error"}}`. Форма любой ошибки: `{"error":{"code":<status>,"message":"…","type":"…"[,"param":"…",…]}}`; все ответы `/admin/*` несут `Cache-Control: no-store`.

## 8. Что приложить к баг-репорту

Обязательно:

1. ID кейса и шаг, на котором расхождение; ожидаемый и фактический результат (цитатой тексты UI).
2. Скриншот UI целиком (шапка с бейджами, вкладка, уведомления/toast, диалог).
3. DevTools → Console: ошибки; DevTools → Network: неуспешный запрос — URL, метод, статус, заголовки ответа (`Cache-Control`), тело ответа (JSON ошибки). Значение заголовка `X-Admin-Key` закрыть.
4. Запись `Activity` (кнопка `Copy record` → вставить текст) или её отсутствие, если ожидалась.
5. Ответы `GET /admin/status` и `GET /admin/diagnostics` с ключом (или `Copy report` из блока `Diagnostics`) — текст, не скриншот.
6. Для неудачного старта модели: строки блока `Last failed start` (кнопка `Copy` есть только в этом блоке — в диалоге `Output of <id>` или в failure-блоке `Model settings`; внизу диалога `Output of <id>` кнопки `Refresh` и `Open settings`, остальной вывод — выделить и скопировать вручную); для загрузок — `GET /admin/models/upload?id=<id>`.
7. Имена и размеры использованных файлов (байты), их SHA-256 для GGUF; для импорта — сам `.settings.json`.
8. Браузер и версия, ОС, второй браузер/устройство (если участвовали), ширина окна (для раскладки).
9. Факты о стенде из раздела 2: GPU/CPU-only и имена устройств, монтирование `/models-rw`, allow-list/nginx, `--models-dir`, `MODEL_DEVICES`, `--api-key`, интернет у сервера; время (с часовым поясом) — для сопоставления с серверным логом администратором.

Никогда не прикладывать: admin-ключ (`X-Admin-Key`, содержимое `LlamaUi.adminKey`), API-ключ (`--api-key`), `HF_TOKEN`, содержимое `localStorage`/`sessionStorage` целиком, файл `admin.key`. В скачанном `provision-admin-audit.jsonl` ключей нет (сервер заменяет их на `[redacted]`), но перед отправкой проверить.

## 9. Особенности по замыслу (не дефекты)

- Публичные маршруты `/models`, `/v1/models`, `/models/load`, `/models/unload`, `POST /models` (скачивание), `DELETE /models` (удаление из кэша), `/models?reload=1`, `/props`, `/health`, `/slots` не защищены admin-ключом и не ограничены allow-list; в `/v1/models` без ключа видны `status.args` моделей. Admin-ключ защищает только `/admin/*`. Об этом говорит заметка под таблицей `Loading, unloading, downloading and deleting models uses the server's public model API; only the settings on this page are protected by the admin key.`
- Неверный ключ на `GET /admin/status` даёт 200 с `authorized:false`, а не 401, и в `Activity` не записывается — это проба, а не отказ.
- Load/Unload/Rescan и все чтения (GET, `Check`, fit-check, dry-run удаления/загрузки) не создают записей в `Activity`; записываются только изменения через `/admin` с ключом, отказы, действия сервера и эффекты публичного API (`Download finished/failed`, `Model removed`, `Model failed to start`).
- Снижение `Max loaded models` ничего не выгружает само; лимит действует при следующей загрузке.
- Смена `GPU for new models` перезагружает список моделей и выгружает работающие cache/models-dir модели без своего устройства (предупреждение показывается заранее). Модели из `models.ini` сохраняют своё устройство; `MODEL_DEVICES` имеет приоритет над всем.
- Проверка размещения только предупреждает: `The check warns only; it never blocks a save.` Проектор (mmproj) в проверку не входит; вердикт зависит от свободной памяти в момент проверки; результат кэшируется 60 с; единицы `GB` с двоичным множителем (расхождение с nvidia-smi \~7%).
- Сохранение значений, равных встроенному default (`Auto (4 slots)`, `f16 (16-bit, default)`, `Auto (on where the GPU supports it)`, ubatch 512), не делает поле `custom` и не требует перезапуска.
- После двух подряд неудачных стартов с сохранёнными настройками сервер сам откатывает их к последним рабочим (или удаляет, если рабочих не было); запуск с клиентским autoload тоже считается попыткой. Значения из `models.ini` не откатываются.
- Скачивание с Hugging Face идёт в кэш (`Model cache`, источник `cache`), загрузка GGUF — в каталог моделей (`Models directory (uploads)`, источник `models dir`, в Docker — `/models-rw/hf` и `/models-rw/local` соответственно); это разные каталоги с разными кнопками удаления (`Delete` / `Delete files`). Модели `preset` из панели не удаляются.
- Одиночный файл публикуется на верхний уровень каталога моделей (`<id>.gguf`); модель с проектором или сплит — в папку `<id>/`.
- Перед публикацией не проверяется, подходит ли проектор к модели: старт такой модели может упасть, для этого есть `Remove only the projector`.
- Сервер держит не более 4 открытых загрузок (включая `Ready`); пятая ждёт. Незавершённая загрузка хранится 72 ч (отсчёт только при работающем сервере).
- Повторный выбор того же файла в другом браузере требует `Take over` только в течение 30 с после последней активности первого клиента.
- Ключ хранится в `sessionStorage` (на вкладку) и, с `Remember on this device`, в `localStorage`; `Lock` в одном браузере не влияет на другой. Только в памяти ключ держится лишь когда браузер запрещает storage (запись бросает исключение); в обычном приватном окне современных браузеров он всё равно попадает в `sessionStorage` вкладки.
- Пункт `Admin` появляется только по единственной пробе `GET /admin/status` при старте приложения; после 403/404 (и после 401 API-ключа на самой пробе — сервер с `--api-key`, сетевая ошибка) он скрыт до перезагрузки или `Retry`; 401 отклонённого admin-ключа на защищённых маршрутах пункт не скрывает.
- Без `PROVISION_ADMIN_TRUSTED_PROXIES` заголовок `X-Forwarded-For` не влияет на доступ и показывается в `Activity` как `via proxy, unverified`; на Docker-стенде Actor записей — адрес nginx, реальный адрес тестировщика — в строке `X-Forwarded-For`. Отказы nginx (замок в прокси) в `Activity` не попадают.
- Отказы одного адреса+пути+причины за минуту сливаются в одну запись с бейджем `counting`; `ip_allowlist` в `GET /admin/status` отражает только встроенный список сервера, при замке в nginx оно `false`.
- Service worker объявляет кэш `api-cache` (NetworkFirst, 24 ч) для публичных `/models`, `/v1/models`, `/props`, `/slots`, но его шаблоны заданы регулярками с якорем `^/`, а Workbox сопоставляет их с полным URL, поэтому кэш, скорее всего, остаётся пустым и чат офлайн показывает ошибку сети; если записи всё же есть, при недоступном сервере чат может показать устаревший список моделей — и то и другое не дефект панели. `/admin/*` не кэшируются никогда.
- Формат ошибок `/admin/*` единый `{"error":{code,message,type[,param,…]}}`. Неизвестный путь (или выключенный админ-API) → 404 `{"code":404,"message":"File Not Found","type":"not_found_error"}` от HTTP-слоя; неизвестная модель в собственном админ-маршруте (`/admin/models/settings`, `/admin/models/log`, `/admin/models/settings/check`) → 404 с сообщением `model '<id>' is not found`; `POST /admin/models/delete` для неизвестной модели отвечает 409 `not_deletable reason not_found`, а не 404.
- Все размеры в панели — двоичные единицы с подписями `B/KB/MB/GB/TB` и тремя значащими цифрами.
